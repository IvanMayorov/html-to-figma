# Технические заметки по сверке сайта и Figma

Читать при сборе DOM-эталона и программных правках макета. Конкретные ID, ширины, количества слоёв, шрифты и цвета каждый раз получать из текущего источника. Приёмы не привязаны к бренду, фреймворку или структуре сайта.

## Измерения браузера

- Сравнивать ширину контента через `document.documentElement.clientWidth`, а не только размер viewport. При полосе 15 px viewport 1935 px даёт контент 1920 px; это пример, не константа.
- Дождаться `document.fonts.ready`, проверить загрузку изображений. Снять координаты через `getBoundingClientRect()`, прибавляя scroll offsets для координат документа. При сборе всех секций использовать одну систему координат и одно состояние страницы.
- Для текста различать внешний element box, content box с учётом padding/border и фактические строки. По `Range.getClientRects()` можно группировать символы в строки и сравнивать места переносов; не путать несколько inline-фрагментов одной строки с разными строками.
- Сохранять исходные фрагменты с font weight/color/decoration, в том числе inline-ссылки, чтобы не превращать смешанный текст в один стиль.
- Получать `backgroundColor`, `backgroundImage`, border по каждой стороне, radius, opacity, размеры, padding/gap; для SVG — fill/stroke и прозрачность каждого нужного пути. Учитывать наследование `currentColor`.
- Снимок полного документа может менять viewport при захвате. Не пересчитывать макет по смещению на половину ширины scrollbar, обнаруженному только на таком снимке. При расхождении повторно проверить DOM при исходной ширине.
- Цветовое преобразование скриншотов и JPEG может сдвигать оттенки. Для заливок и текста авторитетны вычисленные значения CSS; снимки нужны для визуального контроля композиции.

## Figma Plugin API

Перед использованием проверить актуальные API/typings через инструменты и инструкции Figma skill. Не предполагать, что любой CSS поддерживается напрямую.

```js
// Пример для текстового узла с одним стилем;
// в смешанном тексте применять соответствующие range-методы.
text.lineHeight = { unit: 'PERCENT', value: lineHeightPx / fontSizePx * 100 };
text.textWrapStyle = 'BALANCE';
```

- До изменения текста загрузить **все используемые начертания** через `figma.loadFontAsync`, включая стилизованные диапазоны. Не заменять отсутствующий шрифт молча.
- Для смешанного текста использовать styled segments и range-методы. Задать процентный line height относительно размера соответствующего диапазона. Проверка только `node.lineHeight` пропустит узлы с `figma.mixed`.
- Для цвета сохранять alpha, переводя его в opacity заливки. Не дублировать непрозрачность и в fill, и в node, если источник не содержит обоих уровней.
- При переносе слоя между родителями пересчитать локальные координаты из абсолютных, учитывая трансформации и порядок слоёв. Отключение layout или смена родителя может изменить геометрию: перечитать bounds после операции.
- Для обычного фрейма пустые `fills` означают прозрачность. Явно задавать белый fill, где он есть у сайта. Проверять clipping, stroke alignment и видимость разделителей после назначения заливки.
- Сохранять существующие image fills, если они соответствуют источнику; не перезагружать фотографии без причины.
- Делать изменения ограниченными партиями по секциям, возвращать компактную сводку и ID изменённых/созданных/удалённых слоёв по требованиям инструмента. Слишком большие код и JSON-ответы могут превысить лимиты. Не печатать base64 изображений в текстовый вывод.
- Не запускать повторно целиком скрипт, использующий уже удалённые ID. После каждой партии обновлять карту слоёв и продолжать с актуальными данными.

## Сверка переносов и высоты

В браузере и Figma одно семейство/размер шрифта может давать немного разные метрики. Порядок исправления:

1. Проверить фактический шрифт, начертание, размер, tracking и ширину content box.
2. Проверить процентный line height, native wrap и режим изменения размера текстового слоя.
3. Сопоставить строки с DOM-эталоном. При необходимости слегка изменить ширину отдельного text box в пределах колонки, сохраняя отступы и редактируемость.
4. Перечитать полученную высоту, проверить расстояние до следующего элемента и нижний край карточки. Визуально осмотреть экспорт.

Особое внимание — длинным заголовкам CTA, описаниям в узких колонках, подписям команды и юридическим реквизитам. Разделять параграфы согласно источнику, а не накладывать несколько текстовых слоёв в одну область.
